# Investigate

Find the symptom, run its check from the repository root, and apply the fix for the cause the check confirms. Tested
with Claude Code 2.1.303 or 2.1.304 (2.1.304 for worktrees) and Codex 0.160.1, except where a row says it was not
tested. [claude.md](claude.md) and [codex.md](codex.md) explain what each harness reads, trusts and enforces.

| Symptom | Likely cause | Check | Fix |
| --- | --- | --- | --- |
| Claude ignores `AGENTS.md` | A `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` exists in the directory of an `AGENTS.md` or one above, so Claude reads that file instead | `sh .agents/skills/agents-layout/scripts/check.sh` names it | Move what the team needs to `AGENTS.md`, then delete it; [adopt.md](adopt.md#a-root-claudemd) |
| Claude ignores `AGENTS.md` | Claude Code older than 2.1.277, which added `AGENTS.md` support | `claude --version` | Update Claude Code |
| Claude ignores `AGENTS.md` | The person turned the support off; Claude Code's changelog says it is set under "Project instructions" in `/config`; not tested here | `/config` inside a Claude session | Turn it back on |
| Claude does not offer a shared skill or command | The `.claude/skills` or `.claude/commands` link is missing or broken; Claude finds them only there | `ls -l .claude` | Cook `#connect --harness=claude`; on Windows, see the links row |
| An allowed command still prompts in Claude | The workspace is not trusted, and Claude ignores the project's allow rules until it is. `claude -p` reports `Ignoring 1 permissions.allow entry ... workspace has not been trusted` | Start `claude` in the repository and look for the trust question | Accept it once, interactively |
| The same message in a worktree, naming `projects["<main checkout>"]` | Claude keys trust on the clone's main checkout, which was never trusted; a worktree of a trusted clone needs no trust of its own (tested) | The path in the message | Start `claude` in the main checkout once and accept the trust question |
| An allowed command still prompts | An `ask` or `deny` from another file matches too and wins; precedence is deny, then ask, then allow, across every settings file | `grep -n '<command>' .agents/permission/policy.yaml .claude/settings.local.json` | Remove the narrower entry, or agree with the team to change the policy |
| An allowed command still prompts | The command does not start with the entry's words: `git -C sub status` is not `[git, status]`, nor is `env X=1 git status` | Compare the command as run with the rendered rule in `.agents/adapters/` | Run it in the form the policy names, or add that form to the policy |
| An allowed command still prompts in Codex | The project is not trusted, so Codex does not load `.codex/rules` | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command>` prints `"decision":"allow"` while the session still asks | Trust the project when Codex asks; its worktrees, inside or beside it, follow its trust (tested). codex-cli 0.160.1 ignores `-c 'projects."<absolute path>".trust_level="trusted"'` |
| A denied command ran | A form the prefix does not cover: arguments in another order, `git -C`, `env`, `bash -c '...'` or a script that runs it | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command as run>` | Add a `claude:` pattern for the form, and accept that Codex cannot match it; [design.md](design.md#a-guardrail-not-enforcement) |
| A denied command ran in Codex | The entry is Claude-only; the Codex rules file lists it as `# Not enforced by Codex, Claude-only: ...` | `grep 'Not enforced' .agents/adapters/codex/rules/cook.rules` | Express it as a prefix if one can, or rely on Codex's sandbox |
| A denied command ran | The run skipped the policy: `claude --setting-sources user`, `codex exec --ignore-rules`, or Codex in a project nobody trusted. Bypass flags do not: denies hold under them (tested) | The launch command, or the loop runner's configuration | The policy cannot prevent this; agree on launch commands, or use managed settings |
| A worker runs what the policy says to ask about, without asking | Claude ran in bypass mode: `policy.yaml` says `bypass: allow`, the adapters were cooked by a release that did not write the refusal, or the run used `--setting-sources user` | `jq .permissions.disableBypassPermissionsMode .agents/adapters/claude/settings.json` prints `"disable"`; if so, the launch command or the runner's configuration | `bypass: refuse` and cook `#connect` again, or set the runner's command to the unattended line in `.agents/README.md` |
| A Codex worker runs what the rules forbid or ask about | The runner passes `--ignore-rules` or `--ignore-user-config`, or runs in a clone nobody trusted; with `--approve-for-me`, a reviewer approves the asks. Codex has no setting that refuses these (tested) | The runner's configuration; the first line of `.agents/adapters/codex/rules/cook.rules` names them | Set the runner's command to the unattended line in `.agents/README.md`, and trust the main checkout |
| In a worktree inside the repository, Claude ignores the worktree's `AGENTS.md` | A `CLAUDE.local.md` in the main checkout, or in a directory between it and the worktree, turns `AGENTS.md` off there; a `CLAUDE.md` in the main checkout does not reach the worktree (tested) | The first row's command, run in the main checkout | Delete it, moving what the team needs to `AGENTS.md`, or keep worktrees outside the checkout |
| Codex sessions miss the context `.agents/hooks/session-start.d/` prints, in a new clone, a checkout whose hooks nobody trusted, or after a cook changed the `SessionStart` entry | Codex trusts each hook entry per absolute path of the main checkout's `.codex/hooks.json`, which its worktrees share, and by the entry's hash, and skips an untrusted or changed entry without a warning ([tested](codex.md#how-it-is-tested) with codex-cli 0.160.1) | `.agents/hooks/session-start codex` prints the JSON outside Codex; `codex exec --sandbox read-only "<any prompt>" </dev/null 2>err.log` then `grep '^hook:' err.log` prints `hook: SessionStart` only when it ran; `grep -n 'hooks.json' ~/.codex/config.toml` lists the entries Codex trusts | Start `codex` interactively in the main checkout and accept the hook review, or pass `--dangerously-bypass-hook-trust` to the run; [codex.md](codex.md#trust) |
| A session-start hook the team wrote disappeared after a cook | `#connect` owns `hooks.SessionStart` in both harnesses and writes it again on every cook | `git log -p -- .agents/adapters` | Move the command into a script in `.agents/hooks/session-start.d/` that prints the context |
| A hand edit to `.agents/adapters/` came back, or a cook proposes undoing it | The edit was to a key Cook renders from the policy, and each cook renders it again | `./cook --dry-run io.github.lmarqs.cookbook:agents:<version>#connect --harness=claude --harness=codex` | Put the change in `policy.yaml`; every other key is the team's, and cooking keeps it |
| Files Cook wrote for a teammate's harness disappeared | Someone cooked `#connect` with only their own harness, which removes what Cook wrote for every harness left out | `git log --stat -- .agents/adapters .codex .claude` | Cook `#connect` again naming every harness the team uses, and commit |
| An unattended Claude run stops or refuses a command | An `ask` entry matched. With `claude -p --permission-prompts none` anything that would ask is refused | `grep -n -A20 '^  ask:' .agents/permission/policy.yaml` | Move the entry to `allow` or `deny` if the team agrees, or keep that task attended |
| An unattended Claude run refuses commands the policy allows | The workspace is not trusted; see the first prompts row | Run it with `claude -p` and read the warning it prints | Trust the workspace once, interactively |
| An unattended Codex run stops or refuses | A `prompt` rule matched under `approval_policy=never`, which has nobody to ask; not tested here | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command>` | As for Claude: move the entry, or keep the task attended |
| A role's deny does not apply | Claude: the run did not add the role's file. Codex: Codex has no roles | Claude: the launch command has `--settings .agents/adapters/claude/roles/<role>.json` | Claude: add it. Codex: [codex.md](codex.md#no-roles) |
| On Windows, `.claude/settings.json` is a one-line text file holding `../.agents/adapters/claude/settings.json` | git checked links out as text, because `core.symlinks` is off; not tested here | `git config core.symlinks` and `git ls-files -s .claude .codex`, which shows mode `120000` for a link | Turn on Windows Developer Mode, `git config core.symlinks true`, delete those files and run `git checkout -- .claude .codex` |
| Personal approvals or a model appear in a commit | A rule saved to the project settings instead of `.claude/settings.local.json` writes through the link into the shared adapter; not tested here | `git log -p -- .agents/adapters .claude` and `git ls-files .claude .codex`, which should list only links | Revert the change, keep the rule in `.claude/settings.local.json`, or propose it in `policy.yaml` |
| A link in `.claude/` or `.codex/` is missing from `git ls-files`, or `git add` says it is ignored | An ignore rule Cook's `harnesses` section does not undo: one after the section, such as `**/.claude`, or one in a global excludes file | `git check-ignore -v --no-index <link>` names the rule; a rule starting with `!` means the link is not ignored | Move the rule above Cook's section, or narrow it so it leaves the links |
| Files in `.claude/` or `.codex/` other than links are committed | They were committed before the layout, or added with `git add -f`; `.gitignore` does not untrack them | `git ls-files .claude .codex` | `git rm --cached <file>` and keep it locally, or move it into `.agents/` |
| An agent's cook prints `approval required; nothing was written` | Cook asks before writing, and an agent has no terminal to answer, so without `--batch-approve` nothing is written | The command as run has no `--batch-approve` before the first recipe | Run it with `--dry-run`, read the diff, then run it again with `--batch-approve` before the first recipe; [adopt.md](adopt.md) |
| A cook fails naming a TOML file and key, saying the key `is written as` a `[k]` table, a `[[k]]` array of tables or a dotted key | The file spreads a key Cook owns whole over a table or dotted keys, which Cook cannot replace without changing what else is there; it writes nothing | `grep -n '^[[:space:]]*\[' <file>` and the key the message names | Rewrite the key inline, as the message's last line says, or delete it and let the cook write it; [adopt.md](adopt.md#risks-a-review-catches) |
| `#connect` fails saying a path `is a file` or `is a directory`, and that the recipe makes it a link | A real file or directory sits where the layout puts a link; replacing it would stop its contents being read, so Cook writes nothing | `find .claude .codex -mindepth 1 -maxdepth 1 ! -type l` | Move a file to the adapter of the same name under `.agents/adapters/<harness>/`, a directory's files into `.agents/`, and cook again; [adopt.md](adopt.md#risks-a-review-catches) |
| A cook fails naming a settings file and key, with a `JSON:` error and `settings files are strict JSON` | The file holds a comment or a trailing comma, which Cook's parser refuses | `jq empty <file>` names the line and column | Remove the comments and trailing commas, then cook again; [adopt.md](adopt.md#bash-rules-in-a-committed-claudesettingsjson) |
| After cooking `#seed` of a new release, `AGENTS.md`, `.agents/README.md` or `policy.yaml` still has the old text | `#seed` writes them once, when absent, and never owns them; only this skill is rewritten | `git diff -- .agents/skills/agents-layout/templates/` shows what the release changed in their templates | Merge the changes that fit into the seeded files by hand; [design.md](design.md#seed-files-and-the-skill-have-different-owners) |
